## §1 — Universal composition concept

**Multimedia composition at world-class scale serves the article's evidence, not its decoration.** A cover image that doesn't reflect the article's thesis is bait-and-switch. A data viz that doesn't materialize the claim is ornamentation. A diagram that doesn't expose the mechanism is filler. Multimedia composition at principal-grade asks: **what visual evidence does this article need that prose cannot supply?**

The marriage of registers (META × NARRATIVE per CD6 thesis) translates structurally to multimedia register: META articles carry code-form heavy / image-form spare / data-viz dense / diagram-heavy; NARRATIVE articles carry image-form heavy / illustration painterly / audio present / video occasional. Multimedia register MUST match prose register or G3 Apple-cohesion fails.

**Examples that prove the concept at world-class scale:**

- **The Pudding** — multimedia IS the article; per-article-as-self-contained-visual-system; multimedia composition is the editorial work, not the post-prose work.
- **NYT Magazine 2026** — bespoke type + photograph + illustration + occasional embedded video; multimedia density per editorial register.
- **Quanta Magazine** — D3-rendered scientific visualizations as evidence; multimedia carries the scientific claim's proof.
- **Stripe Press** — code-block + diagram + occasional video; META-canonical multimedia register; sparse and load-bearing.
- **The Verge** — heavy multimedia density sustainable through tooling discipline; cross-platform variant generation as structural advantage.

**Prime's expression — 12 cover image recipes + 24 inline multimedia type recipes + per-tool Claude prompt scaffolds + DLDS write-time integration.** Multimedia composition is a 10-15 min Phase 4 task (per pipeline-runbook.md §2.4); recipes operationalize the 10-15 min budget so quality holds without bespoke per-article composition labor.

## §3 — Inline multimedia recipes (per multimedia-audit.md groups)

Inline media fires when prose alone cannot supply the evidence. Per pipeline-runbook.md §2.4 — lightweight inline media (1 code block; 1 inline diagram) can author in Phase 3; heavyweight inline media (data viz; scrollytelling; video) defers to Phase 4.

### §3.1 — Code-form inline (META primary)

| Type | Tool | Recipe |
|---|---|---|
| Code block (source) | Shiki build-time | Wrap code in MDX fence with language tag + filename meta; Shiki applies syntax highlighting at build; CopyButton component (#6 CD4) wraps |
| Code diff | Shiki + diff2html | Use CodeDiff component (#27 CD7) with `before`/`after` props; highlightLines array marks changed lines |
| Terminal output | Shiki shellscript grammar + ansi-html-community | Wrap in CodeBlock with `variant="terminal"`; preserve ANSI color via ansi-html-community |

| Type | Tool | Recipe |

## §8 — Composition principles (when to use what)

When recipes don't cover the edge case, fall back to these principles. Per `feedback_metric_vs_gate_discipline.md` — gates not targets.

### §8.1 — Cover image principle hierarchy

1. **Cover-as-evidence first.** If the article shows shipped code, cover = CodeDiff hero. If the article shows performance, cover = data viz hero. If the article shows decision, cover = architecture diagram. Cover-as-evidence outperforms cover-as-decoration at world-class scale.
2. **Cover-as-atmosphere second.** When evidence cannot be visualized (philosophical / register-statement / Mayor-direction), cover = Firefly painterly atmospheric tied to thesis. Atmosphere is structural; it is not decoration.
3. **Cover-as-character third.** When the article centers a character (agent-creation; profile-piece), cover = character portrait (Recraft consistency OR photograph). Character anchor IS the article's institutional signal.
4. **Cover-as-cosmology fourth.** When the article centers institutional direction (Mayor-direction; lighthouse-arc), cover = cosmology cartography frame + painterly overlay. Cosmology anchor IS the institutional voice.

### §8.2 — Inline media principle hierarchy

1. **Inline = evidence that prose cannot supply.** Diagrams show structures prose describes weakly. Data viz materializes claims prose only states. Code blocks show what shipped.
2. **Inline density per register.** META = code-form heavy; NARRATIVE = image-form light with audio present; INTERPLAY = pivot moments deserve their own dense multimedia.
3. **Inline accessibility floor.** Captions on every multimedia. Transcripts on every audio. Alt-text on every image. WCAG 2.1 floor non-negotiable per CD6 §0 reading discipline.

### §8.3 — DLDS provenance principle

1. **Every AI-touched asset declares.** No exception. ai_role + lane_schema + IPTC/C2PA chain. EU AI Act August 2 2026 readiness at $0 incremental.
2. **Provenance band visible per article.** DldsPanel at footer; consistent placement; reader sees the disclosure structurally.
3. **Provenance accurate.** ai_role matches actual co-authorship split; not aspirational; lane_schema matches actual lane.

### §8.4 — Apple-cohesion principle

1. **Cross-modal cohesion gates everything.** G3 Apple-cohesion test fires per article; multimedia register must match prose register; no multimedia ships without G3 pass.
2. **Cover-prose-chrome cohesion test.** Read article cover + opening pivot + chrome (DldsPanel + ChapterRail + navigation). All three carry the same register or G3 fails.
3. **Cross-platform cohesion test.** Article variants on LinkedIn + Hashnode + Bluesky carry the same register as canonical microsite (per platform's native conventions). Same article, same Prime; G3 applies at variant level too.
