## §4 — Per-component 7-field spec template

Per master plan §3.A CD4 row: *"Per-component spec.md authored: structure / variants / states / a11y / motion / theme / tokens."*

Each per-component spec.md scaffolds the following 7 fields. Per CD1 thesis: spec scaffolds Field 7 token references using typeface-slot citation discipline (5-typeface containment governance) — never hex literals, never raw font names.

### Field 1 — Structure

The DOM / accessibility-tree / semantic-HTML composition the component renders. Describes:

- Top-level element role (e.g., `<nav>` / `<aside>` / `<button>` / `<article>` / `<section>`)
- Slots / composition pattern (e.g., "ChapterRail composes a `<nav>` containing `<ol>` of `<li>`-wrapped chapter links + a `<aside>` for collapsed-state preview")
- Three-layer directory destination per master plan §4 W3 Stream-B deliverable (`/components/ui` shadcn base / `/components/custom` Prime extensions / `/components/patterns` business compositions)
- **Mode-crossing declaration** (per CD1 Concept 7 porous gradient): which surfaces render this component? Article-only? Reception-only? Cross-surface chrome? When cross-surface, what changes per surface? Load-bearing for the metaphor's coherence.

Description discipline: **structural / behavioral / semantic** — NOT visual / aesthetic. Visual aesthetic is encoded via tokens (Field 7); structure encodes role + composition.

### Field 2 — Variants

Discrete variant set the component supports. Each variant cited with its trigger condition (which prop / which context / which content-type triggers the variant). Variants are SEPARATE from states (Field 3) — variants are content-type / context decisions; states are interaction / lifecycle decisions.

### Field 3 — States

Interaction + lifecycle states the component cycles through. Each state cited with its trigger (interaction event / network state / component-internal lifecycle):

- Interaction states: `idle` / `hover` / `focus` / `active` / `disabled`
- Lifecycle states: `loading` / `loaded` / `error` / `empty`

Per master plan §6.6 Row 6 (accessibility) — every interactive state must be axe-core compliant; spec scaffolds the keyboard-navigation pattern + focus-management contract.

### Field 4 — Accessibility (a11y)

Per master plan §6.6 Row 6 (axe-core; every PR; zero violations; W3+ activation). Each component spec scaffolds:

- ARIA roles + labels (every role cited with semantic justification)
- Keyboard navigation (tab order / arrow-key handling / escape / enter behavior)
- Screen-reader behavior (live regions / announcements / structural hints)
- **Color contrast contract** — APCA threshold per text-on-background pairing per master plan §3.A CD2 row (CD2 ratifies; CD4 spec cites the pairing requirement)
- **Reduced-motion contract** — per master plan §6.6 Row 6 + Row 22 (Vibe Fidelity) + per CD5 motion register; spec scaffolds the `prefers-reduced-motion` fallback per component

### Field 5 — Motion

Per CD5 motion + atmosphere workshop output (read as stub if CD5 not yet ratified per master plan §5.9). Each component spec scaffolds:

- **Motion register applied** — Motion v12 / GSAP / Lenis with single-rAF discipline per master plan §3.A CD5
- **Per-state motion** — state-transition animations (e.g., ChapterRail collapsed→expanded; DldsPanel disclosure-animation; SearchPalette open/close)
- **Reduced-motion fallback** — Field 4 cross-reference (same fallback contract)
- **Atmospheric chrome interaction** — per CD1 thesis Concept 4 motion-coupling rule: atmospheric chrome tokens animate ONLY at theme-cycle transitions + very-slow ambient drift; substrate static at typical scroll cadence (protects motion-performance budget per master plan §6.6 Row 13)

### Field 6 — Theme

Per master plan §3.A theme system + §4 W2 token-pipeline output. Each component spec scaffolds:

- **Theme tokens consumed** — light / dusk / dark per CD2 ratification; reduced-motion-light / reduced-motion-dark variants
- **Theme-cycler integration** — per CD5 theme-cycler motion spec
- **Per-theme token pairing contract** — e.g., ChapterRail uses `tokens.theme.<theme>.surface.elevated` for collapsed-state background

### Field 7 — Tokens

Per master plan §6.6 Row 1 (token contract — DTCG 2025.10 schema validation; every push to canon; W2+ activation). Each component spec scaffolds (cite by reference, not value):
