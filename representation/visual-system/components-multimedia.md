## §1 — Universal multimedia component concept

**Multimedia content needs component classes that flex across Building shapes (per Principle 4 — class versatility).** A VideoEmbed that handles editorial / app / dashboard / cinematics; an AudioEmbed that handles podcast / ambient / spatial; a CrossfireShowcase that handles per-article facade + site-wide gallery + tentpole sub-pages. Component classes are inclusion-decisions per Building (does this Building need this class?); tools within the class compose freely (per Principle 1 — composite-utility = universality).

**Examples that prove the concept at world-class scale:**

- **Stripe Press** — Mux video + custom audio embed + interactive demo + designed-object sub-pages
- **Pudding** — per-article-as-self-contained-visual-system; custom components per article; D3 + Scrollama
- **Vercel docs** — Mux video + CodeBlock + InteractiveDemo + Documents-shaped engagement
- **Cloudflare docs** — Cloudflare Stream + tldraw diagrams + interactive playgrounds

**Prime's expression — 11 NEW multimedia components beyond CD4's 20-inventory.** Each component-class scaffolds the CD4 7-field spec template (structure / variants / states / a11y / motion / theme / tokens) at W3 implementation; per-component spec.md authored at canonical path per CD4 §4 pattern.

## §3 — Per-component spec scaffolds (catalog header + rationale; full spec.md at W3)

Each NEW component scaffolds CD4 §4 7-field spec template at W3 implementation. This catalog provides the **header + rationale + tier-tagged tooling reference** per component; full spec.md authored at W3 instance per CD4 pattern.

### §3.1 — CrossfireShowcase (#21 NEW)

**Universal concept.** Replaces traditional social-share buttons with multi-platform preview-card UX. Pentagram-positioning move (no shipped exemplar at principal grade — DISpatch defines the pattern).

**Three composition shapes per `cd7-content-pipeline-stack.md` §3.1:**

- Shape A — Per-article facade row at article-foot (cached OG thumbnails NOT live iframes)
- Shape B — Per-article tentpole sub-page (`/dispatch/<slug>/crossfire`; 2-4 per quarter for marquee articles)
- Shape C — Site-wide gallery (`/crossfire`; latest N articles' multi-platform spread; brand-claim asset)

**Tooling tier (per `cd7-content-pipeline-stack.md` §11):**

- **In stack:** Custom Astro component + cached OG fetch (build-time) + `<bsky-comments>` web component for Bluesky thread integration on tentpole sub-pages
- **In consideration:** Iframely (1800+ domain parsers; predictive sizing CLS-safe) / self-hosted fork `joelabair/iframely`
- **Deferred:** Live oEmbed iframes for LinkedIn / Mastodon / Threads / Meta family (high maintenance debt; revival = aggregate platform-API stability proven)

**3-layer destination:** `/components/patterns` (compound; site-page + per-article variant)

**Mode-crossing:** Both — site-page (`/crossfire`) + per-article (article-foot facade) + sub-page (`/dispatch/<slug>/crossfire`)

**W3 spec scaffold path:** `representation/visual-system/components/CrossfireShowcase/spec.md`

### §3.2 — VideoEmbed (#22 NEW)

**Universal concept.** Mux player wrapper for adaptive bitrate streaming + auto-captioning + analytics + CDN delivery. Industry standard at principal-grade (Stripe Press / Linear / NYT use it).

**Tooling tier:**

- **In stack (CDN):** Mux (bedrock per master plan §1.5 multimedia)
- **In stack (player):** Mux Player
- **In consideration (CDN):** Cloudflare Stream (post-Astro acquisition stack alignment) / Bunny.net Stream
- **In consideration (player):** Plyr (OSS MIT; lightweight) / Video.js
- **Deferred:** Vimeo / Wistia / YouTube embed (canonical) / Self-host MP4 + R2 / Shaka Player

**3-layer destination:** `/components/custom`

**Mode-crossing:** Article-only

**W3 spec scaffold path:** `representation/visual-system/components/VideoEmbed/spec.md`

### §3.3 — AudioEmbed (#23 NEW)

**Universal concept.** Composite component handling 3 modes: `waveform` (Wavesurfer.js for podcast/interview register) + `ambient` (Howler.js for sonic-system audio-palette companion) + `spatial` (Howler.js for multi-source / 3D positional audio for music-app demos / interactive sound-design pieces).

**Tooling tier:**

- **In stack (waveform mode):** Wavesurfer.js (BSD-3) — per CD6 sonic-system §3.3 NARRATIVE article-opener `ambient-warm-high`
- **In stack (ambient + spatial mode):** Howler.js (MIT) — couples to sonic-system audio-palette per CD6
- **In stack (storage):** Cloudflare R2 OR AWS S3
- **In consideration (player):** Plyr (audio + video unified component-class) / Mux Audio (SaaS-grade scale)
- **In consideration (engine):** Tone.js (music-app oriented; can compose with Howler)
- **Deferred:** Mediaelement.js / Web Audio API direct / SoundCloud-Spotify embed

**3-layer destination:** `/components/custom`

**Mode-crossing:** Article-only + LiveTicker integration

**Reduced-motion + reduced-data discipline:** NEVER autoplay; user-initiated only; suppress when `prefers-reduced-data` signals; per CD6 §0 reading discipline.

**W3 spec scaffold path:** `representation/visual-system/components/AudioEmbed/spec.md`

### §3.4 — ImageWithCaption (#24 NEW)

**Universal concept.** Universal HTML primitive — `<figure>` + `<img>` + `<figcaption>` + DLDS provenance band reading C2PA metadata via `@contentauth/c2pa` JS. Variants: `default` / `monospace meta-caption for terminal output` / `cosmology cartography frame caption` / `photograph with IPTC 2025.1 metadata`.

**Tooling tier:**

- **In stack (image processing):** Astro `<Image>` (build-time AVIF/WebP/JPG format negotiation; OSS MIT; bedrock)
- **In stack (C2PA reader):** `@contentauth/c2pa` JS (Adobe-maintained OSS) — reads Adobe Firefly + LinkedIn auto-watermark metadata
- **In consideration:** `c2pa-rs` (Rust core via WASM if perf becomes bottleneck on metadata-heavy galleries)
- **Deferred:** Truepic SDK / Numbers Protocol (alternative provenance standards; overlap with C2PA)

**3-layer destination:** `/components/custom`

**Mode-crossing:** Article-only

**EU AI Act August 2 2026 compliance:** DLDS provenance band reads C2PA content credentials per `feedback_brand_track_dlds_locked.md`; LinkedIn auto-applies "cr" watermark when C2PA present on upload.

**W3 spec scaffold path:** `representation/visual-system/components/ImageWithCaption/spec.md`

### §3.7 — CodeDiff (#27 NEW)

**Universal concept.** Source code + git-diff rendering with syntax highlighting + diff structure. Three render modes: `inline` (Shiki only) + `diff-unified` (Shiki + Shiki diff transformer; +/- markers in single column) + `diff-split` (Shiki + diff2html for full git-PR-review UX).

**Tooling tier:**

- **In stack (highlighter):** Shiki (OSS MIT; build-time; VS Code TextMate grammars; 200+ languages)
- **In stack (diff frame):** diff2html (OSS MIT)
- **In stack (terminal mode):** Shiki shellscript grammar + ansi-html-community (OSS MIT, ~3kB)
- **In consideration:** Monaco Diff Editor (Microsoft; VS Code's actual diff engine; ultimate fidelity) / GitLens-inline (inline blame + diff for git-history-viewer UX) / xterm.js (full terminal emulator; interactive replay) / asciinema-player (timed replay) / react-diff-viewer-continued (React-native alternative)
- **Deferred:** Prism (runtime JS highlighter) / Highlight.js / Starry Night (GitHub Markdown-fence-syntax fidelity edge case)

**3-layer destination:** `/components/custom`

**Mode-crossing:** Article-only + LiveTicker integration (change-log entries)

**Typography slot consumption:** Meta-code typeface (component-locked per CD1 5-typeface containment)

**W3 spec scaffold path:** `representation/visual-system/components/CodeDiff/spec.md`

**Tooling tier:**

- **In consideration:** Replit (collaboration + Replit Agent integration) / Bolt.new (StackBlitz AI-native variant) / CodePen (front-end specialist)
- **Deferred:** JSFiddle / Glitch

**3-layer destination:** `/components/patterns`

**DLDS integration:** Third-party iframe surfaces in DldsPanel (#7 CD4) — discloses external sandbox provider per `feedback_brand_track_dlds_locked.md`.

### §3.9 — DataViz (#29 NEW)

**Universal concept.** Charts + interactive visualizations + LinkedIn Documents PDF export hook (Documents +14% YoY engagement per Subagent 4 research). Three-mode component: `plot` (Observable Plot — high-level grammar-of-graphics; default 90% of cases) + `d3` (low-level craft; bespoke editorial visualizations) + `vega-lite` (declarative JSON spec; AI-agent authorable).

**Tooling tier:**

- **In stack (high-level):** Observable Plot (OSS ISC; Mike Bostock's grammar-of-graphics built on D3)
- **In stack (low-level):** D3.js (OSS BSD-3) — canonical at NYT Upshot / Pudding / FiveThirtyEight
- **In stack (declarative):** Vega-Lite (OSS BSD-3) — LLM-friendly JSON spec
- **In consideration:** Apache ECharts (heaviest feature set) / Recharts (React-native) / Visx (Airbnb React+D3 hybrid) / Nivo (server-side rendering support)
- **Deferred:** Chart.js / Plotly.js / Highcharts (commercial license) / G2 (Chinese ecosystem)

**3-layer destination:** `/components/custom`

**Mode-crossing:** Both — article + Reception dashboard (LiveTicker + EditorialDigest data overlays)

**LinkedIn Documents export hook:** chart → SVG → multi-page PDF generator → LinkedIn Document upload (Documents +14% YoY engagement validates dev-diary thesis).

**W3 spec scaffold path:** `representation/visual-system/components/DataViz/spec.md`
