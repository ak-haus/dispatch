## The governing findings

1. **The eight stages are real; teams run them as three layers, not a sequence** (https://www.intodesignsystems.com/agentic-design-systems): (L1) machine-readable foundations — tokens + brand contract; (L2) agent-queryable infrastructure — component registry/docs, design-to-code; (L3) automated verification + feedback — visual gates, semantic review, analytics. Ideation and authoring are lanes feeding the layers, not gates in them.
2. **Precedent strength ranks (research verdict):** Stages 2, 3, 4, 5, 7 have **strong** 2025-2026 precedent — DTCG tokens spec stable at 2025.10 (https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/), Storybook MCP + official AI story guidance (https://storybook.js.org/docs/ai), DESIGN.md as a published Google Labs spec (https://github.com/google-labs-code/design.md), Figma's design-systems-as-agent-guardrails thesis (https://www.figma.com/blog/design-systems-ai-mcp/), visual diffs as agent feedback loops (https://tweag.github.io/agentic-coding-handbook/WORKFLOW_VISUAL_FEEDBACK/). Stages 1, 6, 8 are **emergent** — real tools, few documented team-scale loops. Stage 4b "semantic review" is emergent and vendor-blog-driven; adopt by function, not vendor class.
3. **The dependency graph differs from the stage numbering.** Stories are the substrate visual testing runs against (today's 5-story seed gives the component-level gate a thin surface; full coverage is what makes it a real gate); tokens must be generated truth before visual baselines are captured (token migration shifts pixels once — the E2E pixel lane may start earlier by accepting **one deliberate baseline re-approval cycle** when Stage 2 lands); the brand contract must exist before generation stages consume it (read-before-generate is the whole DESIGN.md/CLAUDE.md pattern). Documented production cases: Indeed's design-system MCP (4,300 prototypes/4 months), GitHub's daily design-QA sub-agents filing issues (https://www.intodesignsystems.com/agentic-design-systems).
4. **Dispatch's live failure mode is the one the industry pattern kills.** The hand-copied `tokens.css` is exactly the dual-source canon drift that single-source DTCG + generated outputs + CI diff gates exist to prevent.
5. **Design-in-code is Dispatch's validated mode.** Canon is repo markdown + tokens, no Figma files exist; the documented counter-current to Figma-translation pipelines (spec-prompt → code, Figma converging on code-as-source-of-truth at Config 2026) matches this posture (https://adplist.substack.com/p/why-i-stopped-prototyping-in-figma, https://www.designsystemscollective.com/figma-config-2026-the-shrinking-distance-between-drawing-an-interface-and-building-it-1b9cd9142fab).

### Stage 2 — Token engine (board S2; absorbs B2)

**Decision:** git is the token source of truth; **Style Dictionary v5** (already installed) is the engine; **DTCG 2025.10** is the format; Supernova is **validated but not adopted**.

- Source JSON in `code/packages/tokens` converts to DTCG 2025.10 (`$value`/`$type`; the spec's first stable release, 2025-10-28 — https://www.designtokens.org/TR/2025.10/format/) and expands from color-only to typography/spacing/motion/radius/shadow, transcribed from CD1–5 canon.
- Two emit targets: (a) CSS variables for ui/Storybook, (b) a `tailwind-v4` format emitting the `@theme` block (reference implementation https://github.com/tokens-studio/sd-tailwindv4). **Repo-specific constraint:** `@theme inline` resolves `var()` chains at build time (project CLAUDE.md) — dawn values go into `@theme`; `data-prime-cycle` dusk/night overrides emit as runtime cascade blocks **outside** it.
- The generated CSS replaces the hand-copy in `microsite-astro` (byte-diff against current CSS before switchover); `pnpm --filter tokens build` becomes a prebuild dependency of the astro build.
- **CI drift gate:** rebuild tokens → `git diff --exit-code` on generated output. Fail-closed, red = do-not-merge, same discipline as the six live gates.

Alternatives: **Terrazzo** (fuller DTCG 2025.10 support + `@terrazzo/plugin-tailwind` — https://terrazzo.app/docs/integrations/tailwind/) wins if SD's known 2025.10 gaps (gradient, duration/motion — https://github.com/style-dictionary/style-dictionary/issues/1590) block motion tokens; swap is cheap, source JSON is tool-neutral. **Supernova** is real and agent-capable (headless CLI, Node SDK, remote MCP on the Free tier — https://developers.supernova.io/latest/supernova-with-ci-cd/what-is-supernova-cli-mrXWAWFd, https://www.supernova.io/pricing) but adds a SaaS sync hop that ships nothing for a solo repo-canon operator; revisit only if Stage 5/7 repo-native docs prove insufficient. **Figma Variables REST API** is out on plan-gating: Enterprise-only on every endpoint (https://developers.figma.com/docs/rest-api/variables/) — revisit only if an Enterprise plan ever exists here. **Tokens Studio** is Figma-plugin-centric (€17–€499/mo — https://tokens.studio/pricing) — revisit if a human designer ever works this system in Figma.

Agent-compat: 100% — files + CLI + existing CI, zero accounts. Cost: $0. Risks: SD 2025.10 gaps (Terrazzo fallback recorded); cycle-theming breakage if the generator emits overrides into `@theme` (build against the constraint; verify with the cache-reset step); migration pixel drift (byte-diff + Stage 4 gate).

### Stage 7 — Brand contract (board S3)

**Decision:** `DESIGN.md` at repo root becomes the agent-facing brand contract — **generated-from-canon, not hand-held**: the token block is emitted by a Style Dictionary format target from the same DTCG source (the contract cannot drift from built tokens because it *is* a build artifact); prose sections are distilled once from CD1–5 + the universal type rules, with pointers into `representation/visual-system/` rather than duplication. CD1–5 remains the locked human canon; DESIGN.md is its compilation.

- Conform to the **Google Labs DESIGN.md spec** (open-sourced April 2026, Apache-2.0, alpha, ~27.3k stars — verified first-hand: https://github.com/google-labs-code/design.md): YAML token frontmatter + markdown rationale; its CLI ships `lint` (11 rules incl. WCAG contrast), `diff`, `export` (Tailwind + DTCG), JSON output for agents. The generation layer insulates canon from alpha-spec churn — the precedented posture for a canon-locked repo.
- Wiring: one pointer line in `AGENTS.md` + `.claude/CLAUDE.md` ("read DESIGN.md before generating or editing any UI" — the Cursor-rules pattern, https://www.designmd.co/d/cursor); CI gate `design-contract-drift` (regenerate → `git diff --exit-code DESIGN.md`); existing design rules **move or pointer-reference** into it, never copy (no second source of truth).
- **`nexu-io/open-design`** (verified first-hand: real, Apache-2.0, ~88.8k stars, created 2026-04, active) is proposed **only as an optional workstation auditor (install-or-skip is register §6)**: its `brand-extract` skill drives the live site and recovers a brand kit (https://github.com/nexu-io/open-design/blob/main/skills/brand-extract/SKILL.md) — an independent check that dispatchmag.dev matches canon — plus on-brand collateral rendering. Free, BYOK. Its headless-CI/MCP story is undocumented `[unverified]` — **never on the critical path**.
- Cross-link: the DESIGN.md lint's WCAG contrast rules will surface the same copper-contrast question as open flag **F5** — one AK canon decision resolves both.

Alternatives: house-shape contract (more expressive for letterpress/cycle rules, less portable — the hybrid of spec-shaped frontmatter + house prose captures both); custom design-system MCP server (https://jamesiv.es/blog/your-design-system-needs-an-mcp-server/) — wins only multi-repo; zeroheight MCP — team-scale SaaS, overkill.

Agent-compat: the deliverable IS agent context — plain markdown + CLI, zero GUI. Cost: $0. Risks: spec is ~4 months old (adoption beyond Stitch/Cursor/Claude readers still forming); prose drift (mitigated by pointers); the two-contracts trap (mitigated by move-don't-copy).

### Stage 5 — Component docs & governance (board S5)

**Decision:** Storybook 9.1 (installed) is the component-doc surface; **agents author the stories** — CSF3 + `tags: ['autodocs']` + variant matrices extending the 5 existing stories to the full `packages/ui` surface (~50 component files), per Storybook's official AI guidance (never hallucinate props; verify with story tests — https://storybook.js.org/docs/ai). The 99 existing vitest tests define the prop surface to enumerate; the 5 existing stories (545 lines) are the house style template. Per-story a11y via the installed addon; the Vitest test addon (`@storybook/addon-vitest`, needs Vitest ≥3 + Playwright Chromium — https://storybook.js.org/docs/writing-tests/integrations/vitest-addon) turns every story into an interaction + a11y test in CI. `storybook build` enters CI; its static artifact is what Stage 4's story lane consumes.

- **Storybook MCP** (`@storybook/addon-mcp` — dev/docs/testing toolsets, self-healing generate→test→fix loop, docs toolset React-only which matches `packages/ui` — https://storybook.js.org/docs/ai/mcp/overview) is the adopt-when-stable rail: its docs are published under v10.5 and 9.1 compatibility is `[unverified]`. Decision: **write stories on 9.1 now as plain files** (no wasted motion — stories are required either way); the 9→10 upgrade is a separate later decision, cheapest while story count is low (AK option).
- **Governance gates:** ESLint token rules (no raw hex/px literals in `packages/ui` + `microsite-astro` components — the only governance form an agent can't argue with; precedent https://medium.com/@barshaya97_76274/design-tokens-enforcement-977310b2788e) as a CI gate, honest **only after Stage 2 lands** (a lint pointing at incomplete tokens forces exemptions).
- **Docs hub:** Storybook autodocs + repo markdown now; **Starlight** (Astro-native, $0 — https://starlight.astro.build/) only if a rendered prose hub is later wanted. **Zensical is not adopted** — real (Material for MkDocs team, launched 2025-11-05, MIT — https://squidfunk.github.io/mkdocs-material/blog/2025/11/05/zensical/) but pre-feature-complete and Python/MkDocs-ecosystem: wrong toolchain for a pnpm/Astro shop.

Agent-compat: stories are plain TypeScript; CLI init/build/test; zero GUI. Cost: $0. Risks: MCP version gap (decoupled — plain-file authoring now); Vitest version alignment with existing suites (check before wiring); LLM story hallucination (acceptance = run-story-tests + a11y green, not story existence).

**Wiring:** (1) once the register-§1 account decision lands — Chromatic Playwright mode on the E2E workflow (`@chromatic-com/playwright` import swap, `--exit-once-uploaded`, `autoAcceptChanges: "main"`, token via `gh secret set`); (2) in parallel and independent of any account — `toHaveScreenshot` locks on the masthead/wordmark surfaces, CI-generated baselines committed; (3) after Stage 5 — Chromatic Storybook mode over `apps/storybook` + TurboSnap. Budget check at full story coverage: 4 E2E pages + ~50 stories × 2 viewports ≈ 105 snapshots/build ≈ 47 builds/mo on the 5,000 free tier before TurboSnap — adequate at solo cadence, and TurboSnap (~5×) restores headroom as the story count grows.

**Flake law (mandatory, not optional):** GSAP/Lenis motion must be settled/disabled at capture and dynamic regions masked, or the gate cries wolf and trains everyone to rubber-stamp — the documented killer of stage 4 (https://github.com/stevekinney/stevekinney.net/blob/main/courses/self-testing-ai-agents/visual-regression-as-a-feedback-loop.md). Chromatic auto-pauses CSS animation; JS-driven motion needs explicit settle logic in the specs.

**Flake law — applied to the archive lane, EXECUTED 2026-08-19 (F19; merged `90855ff`).** The law shipped for the pixel floor but not for the Chromatic e2e lane, which archived by accident: `@chromatic-com/playwright` snapshots every test's final DOM unless told otherwise, so all 39 tests shipped an archive (a *failing* test too — an assertion failure does not propagate through the fixture), and the lane drew changes on every commit including a pure-CI one. Diagnosis by measurement, not inspection: the same commit run twice, archives hashed and compared — **21 of 39 differed**, from two causes, mid-motion inline styles (74 nodes; Motion writes `transform`/`opacity` on the main thread, invisible to `getAnimations()`, so `settleMotion` alone was never sufficient — the 404 archive was shipping its masthead at `opacity: 0`) and genuinely live regions (40 nodes: wire timestamps, freshness lines, an infinite cue, a GSAP marquee). The repair is narrowing, not disabling: **auto-archiving off** (`disableAutoSnapshot` in `playwright.config.ts`), **six chosen surfaces** opting in by name through `archiveSnapshot()` (`e2e/helpers/archive.ts`) — home cover ×2 viewports, article, `/wire`, 404, figure proving ground — each gated behind a rest probe that **fails the test** rather than archiving mid-motion, and live regions **declared in the markup** as `data-live` (skipped by the probe, excluded from the diff via `ignoreSelectors`). Result on the same two-run measurement: **6 archived, 0 differing nodes outside a declared-live region** — re-runnable via `scripts/measure-archive-determinism.mjs`. Coverage is held by `scripts/check-archive-coverage.mjs` inside the existing `e2e (playwright + axe)` context (no new ruleset seat). Snapshot budget: 39/build → 6/build.

**Stage 4b — semantic judge (in-house):** "semantic review" as a named stage is **emergent, not standard** (honest verdict) — the practiced pattern is agent screenshot-review loops (https://shipyard.build/blog/playwright-mcp-screenshots/). Decision: a `semantic-review` CI job reusing the Playwright config — screenshots of ~4-6 route/scroll states × 2 viewports → Claude vision judges against DESIGN.md (wordmark rule, 12px floor, letterpress, palette) → structured findings on the PR. **Superseded 2026-08-19 (register §8): the judge is AK.** The CI job keeps the deterministic screenshot pass and publishes it as an evidence packet per PR; the vision-model verdict, its calibration window, and the ratchet-to-blocking are withdrawn (evidence: wiki 16 — F1 10–31% on fine-grained design defects across all frontier VLMs; zero shipped LLM-judge-as-gate precedent). The implementation stays dormant in-tree, re-armable by register decision. *Originally: report-only during a 2-week calibration window, then ratcheted to blocking (pinned model, structured rubric, deterministic screenshots).* DESIGN.md remains load-bearing — the mechanizable half of the contract belongs in deterministic checks (the open half of board flag R1). **Autonoma** (verified real: agentic *functional* E2E, natural-language tests, OSS self-host + free cloud tier 100K credits, MCP server, llms.txt docs — https://getautonoma.com/, https://docs.autonoma.app/) is an optional later add for functional coverage; it is not a brand-fidelity tool. Semantic review **complements, never replaces** the pixel gate (https://www.refontelearning.com/blog/visual-regression-testing-ai-test-agents-miss).

Agent-compat: Chromatic CLI/Action/API + in-house judge = agent-drivable end-to-end; the one recurring human surface is diff review, which is policy (AK option), not mechanism. Cost: $0 (+ judge's vision calls, cents to low dollars per PR depending on model tier). Risks: snapshot budget exhaustion as stories multiply (TurboSnap + viewport discipline); Chrome-only leaves Safari `mix-blend-mode` letterpress rendering untested until paid (real risk — recorded, not solved, at $0); GraphQL reviewTest plan-gating `[unverified]` → fallback is branch auto-accept policy + AK web review; LLM-judge nondeterminism (calibration window + pinned model).

### Stage 8 — Authoring (board S8, new row)

**Decision:** **no CMS.** Schema-checked MDX-in-git IS the industry-validated authoring surface for an agent-authored, AK-approved editorial flow: agents draft/edit `src/content/dispatch/*.mdx`, the zod schema in `src/content.config.ts` is the named editorial contract, the existing astro-build CI gate is the enforcement, PR review is AK's sign-off. It cannot open this project. **Keystatic** (free, git-based, Astro-recommended — https://docs.astro.build/en/guides/cms/keystatic/) is the reversible additive option if AK ever wants browser hand-editing; agents route around any GUI either way.

Agent-compat: maximal (files + git + CLI). Cost: $0. Risk: the contract only holds while the build gate stays fail-closed.

**Stage status — OPERATIONAL 2026-08-19 (S8 build).** Shipped: `content (schema gate)` (`.github/workflows/content.yml`, registered on ruleset `21012416` as required context #15) + the authoring section in `AGENTS.md`. Proven on a real content path, not a fixture: `dispatch-03.mdx`'s `readingTime` was deliberately broken, the gate went red, the file was restored, the gate went green. **The mechanism runs `astro sync`, not `astro check`** — `check` runs `sync` first and then repeats what `typecheck (tsc)` already requires (microsite-astro's own `typecheck` script *is* `astro check`), so a second full check would be decoration; `sync` is the content-validating core, running the real glob loader against the real zod schema, so no second source of truth exists to drift. **The stated rationale is amended by measurement (no silent overwrite):** *"content PRs fail in seconds instead of after the full build"* is only partly borne out — real CI wall clock on the broken commit was `content (schema gate)` **23s** · `build (astro)` **26s** · `typecheck (tsc)` **32s**, because Astro syncs content before bundling, so the build was never slow at this error class. The gate's real earnings are (a) a red context **named for the editorial contract** rather than a generic build failure, and (b) content-failure latency that no longer depends on Astro's internal step ordering. Scope measured and recorded, not assumed (astro 6.4.8): malformed YAML → caught; zod violation → caught, with file + field named; **MDX compile/import error → NOT caught** (rollup resolves imports only at build) — `build (astro)` owns that half and the two gates layer. `sync` needs no tokens build (verified with `packages/tokens/dist` absent), no generate scripts, no network. Deferral honored: no schema change — widening the contract is AK's editorial call.
