## What landed

One derivation per datum, lifted from the one place each rule already existed and shared by every
surface that shows the datum. None of them widens the contract.

| Datum | Rule, and where it came from | Consumers |
|---|---|---|
| Which dispatch is newest | `newestFirst`: date, then id (the feed's, B18) | home, `/article`, `/sitemap`, feed |
| A dispatch's number | `dispatchNumber(id)` (the dispatch page's "Dispatch NN") | dispatch page, featured Series, grid folios |
| A dispatch's date | `formatDispatchDate`, ISO 8601 (its page's) | every listing and the page |
| The edition dateline | the newest dispatch's date, long form, static | cover, marginalia, featured, colophon |
| A dispatch's cover | `dispatchCover`: hero, else its plate, else **nothing** (the share card's rule; the card alone keeps the site-plate fallback a link preview needs) | page banner, grid, `/article`, share card |
| The pull quote | its authored `<PullQuote text>`, read from the MDX tree at compile time | featured spread |
| The Editor's note | the contract's `provenance.summary` (what its page discloses) | featured spread |
| The typeface credit | the primary face of each slot in `typography.json` (the DTCG source) | colophon |

**The pull quote runs on Astro 7's real seam.** Astro 7 renders `.md` and `.mdx` on Sätteri, and
`markdown.remarkPlugins` no longer runs there. The build refused the config and named the fix. The
documented extension point is `markdown.processor: satteri({ mdastPlugins })`, with
`@astrojs/markdown-satteri` installed at the exact 0.4.1 Astro pins. The plugin only reads. **All six
dispatch pages are byte-identical to `main`** after normalizing hashes and island ids. That covers
prose, head and share metadata, and so also proves the processor swap and the dispatch layout's
move onto the shared rules.

Also removed: the per-card `LIVE` beacons (and their infinite pings), "today" in every form, the
invented sender, domain, tags and handle fallbacks, the next-edition card, and the dead `authorHandle` and
`siteUrl` fields. Depicted avatars now show the initials of the name printed beside them. The
LinkedIn depiction shows the account the surface names (`handle`) rather than the dispatch's byline.

## Two instruments this build had to correct

- **The F65 byte pin double-counted.** Chrome reports each chunk's `encodedDataLength` one
  `dataReceived` event late: `[0, 134898] [134898, 188168] [188168, 0]` for a 323,066-byte plate. So
  `encodedDataLength || dataLength` counted every request's first chunk twice. That's +40% to +100%
  per image, which read six real covers (1.649 MB, equal to the sum of their `content-length` to the
  byte) as 3.3 MB. The pin now sums `dataLength`, which is exact for media that is never
  content-encoded, and still counts an aborted request's chunks. **Negative-tested against Build 31's
  build** (`b5dedb1`, before F65): the corrected pin still fails it at 2.58 MB. On this branch it
  reads 1.649 MB at desktop and 0.820 MB on a phone.
- **The F55(4) pins lost their subject, and were retargeted rather than skipped.** They hover a
  video card, and the only video cards were the synthesized ones. Their `n > 0` precondition refused to
  pass vacuously, which is correct. The player and its reduce gate are still the reading room's
  answer for a declared video cover, so they get the house's proving ground:
  `/preview/reading-room`, on `/preview/figure`'s pattern (noindex, sitemap-excluded, documented).
  It shows the real listing with one fixture video cover. It joins the reflow sweep and the
  proving-ground share-metadata law.

A third, recorded for every future agent session: **Astro 7 backgrounds `astro preview` when it
detects an agent** (`AI_AGENT`, `CLAUDE_CODE_*`, …). The detached server outlives the command and
pre-scans `dist/`, so it goes stale across rebuilds. It served one probe run of this build before it
was caught, and every reading was re-taken on a fresh, owned server. `ASTRO_PREVIEW_BACKGROUND=1`
keeps it in the foreground. CI and the Playwright container are unaffected because they carry no
agent env. Filed as F73.

## Filed, not fixed — each with its session named

- **F71 — decorative platform chrome renders live controls, and focus on them is hidden.** The
  Crossfire depictions carry six `<button>`s (`+ Follow`, Like, Comment, Repost, Send, `⋯`). Measured
  on this branch's build at 1280×800: all six are tab stops, none carries a handler (read from React's
  own props, since React delegates events and `onclick` is always null), and **each one, once
  focused, is 0 of 9 sampled points visible**: it sits on the LinkedIn dossier, stacked beneath
  another. The detector was proven first on a deck link that reads 9 of 9. That is a **WCAG 2.2
  SC 2.4.11 (Focus Not Obscured, AA) failure**, the keyboard-floor class (F56) rather than invented
  data, so it fails this build's defer test (it does not block F61's gate). The 375 reading is
  not claimed, because the control itself failed at that width. **Session: Build 34, its own small
  Phase C build, before D1.** Golden's gate is conformance, so this cannot wait on F68's
  copper-register build, which is off the golden path. The fix is markup-sized: a depiction is not
  a control.
- **F72 — `readingTime` is authored, and wrong.** It reads `4 min read` on all six against measured
  bodies of 333–479 words. The component renders the contract faithfully, so this is content plus
  contract design, and it is **AK's**. The field's answer is to compute it: Astro documents a
  recipe that derives it from the body at build time, and Brysbaert's 2019 meta-analysis puts silent
  reading of English non-fiction at about 238 wpm, so these bodies take 1.4–2.0 minutes and every
  one rounds up to `2 min read`. **Options,
  ranked by what they achieve:** (a) derive it and retire the authored field, which is a contract
  narrowing that ends the drift for good; (b) keep it authored and add a build check that fails on
  a disagreement past a minute; (c) correct the six values by hand, which fixes today only.
  **Recommended: (a).** **Session:** AK's ruling, then a small build.
- **F73 — Astro 7 backgrounds `astro preview` under agent detection** (above). It is an instrument
  hazard for any agent session that probes a locally served build (C1's lenses did). **Session:** a
  checkpoint adds it to AGENTS.md §Commands.
