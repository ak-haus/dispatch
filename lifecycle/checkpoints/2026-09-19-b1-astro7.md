## The two things Astro 7 broke — found, root-caused, fixed at source

- **The prerender import of `cookie`.** Astro 7's prerender step imports its own bundled output from
  `dist/.prerender/`, and that output keeps Astro's `cookie` import external. Under pnpm's strict
  layout the bare specifier cannot resolve from the app. Here it walked up to a stray
  `C:\Users\AKALM\node_modules\cookie@0.7.2` outside the repo, which lacks `parseCookie`, and the
  build failed. On a clean CI runner it would not resolve at all. **Fix:** `resolve.noExternal:
  ['cookie']`. This is Astro's own upstream remedy for the same class (`ALWAYS_NOEXTERNAL` bundles
  `neotraverse` "so the prerender output resolves Astro's own copy", withastro/astro#17508). Vite 8
  documents `resolve.noExternal` as "previously `ssr.noExternal`"; measured, `ssr.noExternal` alone
  does not reach Astro's `prerender` environment. `sharp` is also external in that output, but it
  loads lazily inside the image service, which no page uses, so it stays inert.
- **Whitespace.** The new default `compressHTML: 'jsx'` glued inline text: "AK Almoumen·Mayor" in the
  article byline, "←Back to DISpatch", and "renders inaccent-prime" on the token page. **Fix:**
  `compressHTML: true`, Astro 6's rendering-preserving compression, as the v7 guide documents for
  keeping the previous behavior. Adopting JSX whitespace would be its own deliberate change.
